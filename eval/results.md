## Summary (measured)

- Quiz items with evidence verified: **325 of 325 (100.0%)**
- Quiz answers manually checked as correct: **75 of 75 unique items (100%)**, I read every item in eval/quiz_dump.md and checked that the marked answer is the only sensible word for the blank, given the evidence sentence. The 13-language runs reuse those same 75 items (325 total): only the question/reason wording is localized, options, answers and evidence are identical, spot-checked in Spanish, Arabic, French and Chinese in the new dump. One weak item, not a wrong one: cells Q5 blanks the filler word "about" ("has ______ 37 trillion cells"), the answer is unambiguous, but it tests a filler word, not understanding.
- Explanations that changed a number or formula: **0 of 65 runs**
- Median time to result (median of the 65 run-medians): **1.17 ms** (in-process engine time only; excludes the 400 ms skeleton pause in the UI)
- Student clarity rating (1 to 5): **not measured** (no student test was run before the deadline)
- AI mode: **measured live, see the AI mode section below**

AI answer times in run 3: 0.2-7.3 s per explanation (fallback is instant). Every language produced an AI explanation in that language at least once (Hindi, Bengali, Arabic, Spanish, French, Portuguese, German, Turkish, Indonesian and Chinese all appear in the run-3 output). One Roman Urdu AI explanation (photosynthesis, runs 2 and 3) had a garbled phrase, but its numbers and formulas were still exact and the quiz (built offline) was unaffected, the number check would have discarded the AI text if a number had changed.

Run 4 quirks: one cells/english explanation came back in Urdu script, correct content, wrong language for the request. This is what motivated the English script check (reject an explanation that is mostly non-Latin script for an English request) and the retry-after-rejection. One Hindi cells explanation had a grammar slip ("जीवित के" for "की"). Numbers and formulas were exact in every run-4 explanation.

Run 5 (59/65) is a little below run 4 (63/65), the free API varies run to run; the retry means a transient failure only becomes a fallback after two tries. Only the last 3 lines of run 5's per-run output were kept, so which of the 6 fallbacks were API failures and which were rejected outputs is not visible in the kept log, the summary (59/65, 0 numbers changed, quiz 325/325) is the measured result.

## What the numbers mean

- Evidence is verified by design in the offline engine: each quiz item blanks a word out of its own evidence sentence, so the sentence is always found in the passage. The check still runs on every item and would flag a fake sentence (see the unit tests).
- Numbers and formulas are copied from the passage, never reworded, so none changed in any run.
